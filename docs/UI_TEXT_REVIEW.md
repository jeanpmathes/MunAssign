# UI Text Review

This document inventories user-facing text found in `app/src/jvmMain` and proposes wording changes for a later UI copy pass. It is intentionally review-only: no Kotlin text has been changed yet.

## Big Changes

- Replace implementation-source language with organizer-facing outcomes. Users should see what a count, chip, or action means for assignment work, not which internal source produced it.
- Use **update** for the online Excel file workflow. Use **import/export** only for `.munassign` conference transfer.
- Avoid naming MunAssign in ordinary status text. Prefer "pending assignment", "confirmed assignment", "online", "delegate", "reservation", and "capacity".
- Keep external/source terms only when the user is selecting or handling a source artifact, such as an online Excel file or `.munassign` file.
- Make destructive or state-changing dialogs explain the practical effect and how to undo it where possible.
- Make short icon tooltips action-oriented and remove trailing periods from terse command tooltips for consistency.

## Style Guide

- Prefer user outcomes over implementation details: "Counts delegates you can still place" instead of "derived from active paid delegates".
- Use "online" for data that organizers understand as coming from the online registration system, unless the action specifically names the source file.
- Use "pending assignment" for app-created assignments that still need confirmation by a later update.
- Use "confirmed assignment" for assignments already confirmed online.
- Use "textual exports" for the markdown recovery folder in visible UI; reserve "markdown" for docs or diagnostics.
- Keep labels short. Put consequences, restrictions, and undo paths in tooltips or dialog body text.
- Accessible descriptions for icon-only controls should match the tooltip command, without extra implementation detail.
